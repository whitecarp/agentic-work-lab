# AI 輔助資料研究：商戶示例

**繁體中文** · [English](business-development_EN.md)

## 從需求到可重用流程

把模糊需求拆成可執行流程，選擇工具，保留資料來源，檢查結果，再把可用的方法整理成團隊能複用的範本。B站專案提供真實的研究、內容交付、排程與數據紀錄；商戶拓展部分是將這套方法用於商戶資料整理的離線演示。

## 示例工作流程

| 日常工作 | AI 協助方式 | 人類決策與交付 |
| --- | --- | --- |
| 商圈與商戶研究 | 整理公開來源、分類業態、標記缺失資料。 | 核對營業與服務範圍，形成一頁簡報。 |
| 線索排序 | 依明確欄位產生可解釋排序。 | 依地區策略與資源調整優先級。 |
| 溝通準備 | 起草價值主張、訪談問題和異議處理。 | 核對承諾與商戶情況，再決定如何聯絡。 |
| 會後整理 | 將會議筆記整理成需求、承諾、負責人與日期。 | 確認重點後更新 CRM。 |
| 團隊分享 | 統一提示詞、欄位、示例與檢查表。 | 共同維護有效做法與失敗案例。 |

## 可執行示例

```sh
npm run demo
npm test
```

輸入為三個虛構商戶，輸出見 [merchant-priorities-demo.json](../results/merchant-priorities-demo.json)。排序採用可解釋權重，缺失服務範圍的商戶會標記為 `research_required`，不會自動發信。此程式處理結構化資料；它沒有呼叫模型，也不把規則評分冒充 AI 預測。

## 小範圍團隊試用

先選一個商圈、一種商戶類型，記錄人工整理一份簡報的時間與錯誤。以相同規格試用 AI 輔助流程，由同事抽查來源、完整度與可用性。只有在實測有收益時才擴展，將範本、示例和常見錯誤一起交接。

建議衡量：每份簡報的中位完成時間、來源可追溯比例、人工更正次數、完成跟進比例。簽約率需要另設觀察期與對照，不能把整理速度直接當成營收成長。這些是試點設計，尚無真實商戶或團隊提效實測。

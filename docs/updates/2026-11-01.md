## 開發與驗證分工

CrossCast 的獨立倉庫仍在處理既有功能驗收。[PR #3](https://github.com/whitecarp/publishops-crosscast/pull/3) 在本輪核對時保持開啟，分支頭為 `80e166b`；本機另有 `988bee2` 候選包，不能把本機候選寫成公開正式版本。本實驗室保留 `0.15.1` 歷史程式快照，本輪未匯入候選程式碼，也未合併 PR。

- `eaa1aab` 的 [GitHub CI](https://github.com/whitecarp/publishops-crosscast/actions/runs/41301333026) 已核實在 Python 3.10／3.11／3.12 通過離線測試、wheel 建置及 CLI 安裝檢查；結果僅對應該提交。
- `80e166b` 有143項本機針對性測試通過；X 書籤夾移除、獨立空清單讀回及清理完成。較早「找不到控制項」的重繪解釋仍是推論。
- `988bee2` 的13項針對性測試通過，但獨立反例仍發現置頂評論識別不夠精確，因此沒有繼續真實置頂測試。抖音已有草稿的防護只驗證至3秒觀察窗。
- YouTube 播放列表選取已通過該次測試，後續排期讀回失敗；抖音排期卡片的時間及私密標記可見，但 CLI 讀回逾時。兩者的臨時項目均已清理，不把原始失敗回執改成成功。

可重用的做法是：交付包綁定版本與雜湊；離線測試、反例、真實操作及清理各自留證；失敗後先核對已有結果，避免重複提交。這些是工程方法，沒有量測團隊節省工時或模型能力排名。

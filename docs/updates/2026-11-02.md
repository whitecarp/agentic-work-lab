直式版重新安排工單與角色面板，並非直接裁切橫片。製作檢查以360像素寬預覽字幕、數字和章的位置；字幕56 px、數字106 px，重要內容放在168–1330 px區域。這是本次構圖的經驗範圍，並非平台官方安全區，也不代表已在所有手機驗證。

製作紀錄量到直式三片響度為 −17.5／−16.6／−17.5 LUFS、峰值約 −1.5 dBFS，沒有削波樣本。橫片舊紀錄曾寫大部分蓋章對齊在6毫秒內，後續逐幀檢查卻發現第一張工單印章約早於聲音130毫秒；其他工單與稱號章仍含按相同時序推算的部分。此處保留這個量測分歧，不把舊數字當成已通過的精度證明。直式11次工單蓋章的製作檢查記錄在一幀內，仍不取代完整聆聽。

## CrossCast：把成功的範圍說清楚

[PR #3](https://github.com/whitecarp/publishops-crosscast/pull/3) 在本輪檢查時尚未合併。以下實測限於候選提交 `2d54c8f`；本實驗室繼續保留 `0.15.1` 歷史程式快照，沒有匯入候選程式碼。

- 該提交的 [GitHub CI](https://github.com/whitecarp/publishops-crosscast/actions/runs/41380631557) 在 Python 3.10、3.11、3.12 通過離線測試、wheel 建置和安裝後 CLI 檢查；本機另通過16項針對性檢查。兩者不是全平台功能驗收的替代。
- X 新上傳可進入正確素材的發布預覽，原始媒體容器與編輯器內的影片來源一致；沒有按下公開發布。測試素材已刪除並重新載入確認不存在。
- 一次遠期 X 排期按下最終 Done 後，獨立檢查找到文字、日期及時間一致的唯一列；排期及素材隨後刪除並讀回確認。CLI 原回執仍是 `SUBMITTED_UNVERIFIED`：該列沒有可持久化的作品／媒體ID配對，不能因看到相同文字便改報完整核驗成功，也沒有驗證未來時間到達後的發布。
- 抖音私密測試片的卡片與編輯頁均讀到完整文字及零個多餘星號；但平台顯示修改審核中。這份快照中尚未執行編輯，測試仍待審核與清理，不能寫成編輯功能已通過。

這些紀錄展示如何把 AI 協助開發的流程做成可交接的工作：版本綁定、針對性反例、一次提交、獨立讀回、清理與待辦分開保存。沒有以測試數量推論商戶成長或團隊節省工時。
